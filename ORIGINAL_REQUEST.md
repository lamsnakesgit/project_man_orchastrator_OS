## Requirements

### R1. Интеграция Antigravity SDK в Celery
Celery-воркеры должны использовать `google-antigravity-sdk` для запуска полноценных AI-агентов, передавая им контекст задачи из Kanban-доски.

### R2. Изолированное выполнение (Git Worktrees)
Для каждой новой задачи бэкенд должен создавать изолированный `git worktree` и новую ветку (`feature/task-<id>`), чтобы агенты могли работать параллельно, не ломая основную кодовую базу.

### R3. Автономный Git Workflow и Юнит-Тесты
После написания кода агент (включая мобильных фронтенд-разработчиков) обязан написать и запустить Unit-тесты. Только при успешном прохождении локальных тестов агент делает коммит, пушит ветку и создает Pull Request. Вливание в `main` происходит после финального апрува.

### R4. Маршрутизация моделей и API (LiteLLM)
Antigravity SDK должен использовать локальный LiteLLM прокси для маршрутизации. Для сложных задач планирования/ревью должны выбираться передовые модели: `claude-3.5-opus` или `gemini-3.1-pro`, а для быстрого рутинного кодинга — `gemini-3.5` / `gemini-3.6`. Выбор модели передается как параметр при запуске агента.

### R5. Омниканальный прием задач и обратная связь
Система должна уметь принимать задачи не только из Kanban UI, но и из внешних систем (Telegram через теги, вебхуки из Asana). По завершении задачи (успех или ошибка) агент должен возвращать статус обратно в исходный канал (например, отправлять уведомление в ТГ или менять статус в Asana).

### R6. Поддержка разных типов проектов
Оркестратор должен быть универсальным. В зависимости от типа проекта (Mobile Dev, Web, Маркетинг) Celery-воркер должен спавнить агента со специфичным набором инструментов (Android CLI, браузерные плагины и т.д.).

## Acceptance Criteria

### Проверка полного цикла задачи
- [ ] При создании задачи через UI или Telegram, Celery-воркер успешно стартует.
- [ ] Воркер создает новую git-ветку и worktree.
- [ ] Antigravity-агент успешно инициализируется в этой ветке, создает текстовый файл-заглушку (для теста) и коммитит его.
- [ ] Агент пушит ветку и создает Draft Pull Request на GitHub.
